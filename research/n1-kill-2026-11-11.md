# N1 week-1 kill test: does the float32 pair-inversion attack survive D2's 5-step FedAvg upload? (2026-11-11)

## Verdict (plain words)

**No. The kill rule triggers: N1's headline does not transfer to FedAvg.**
- **One step:** when a sensor uploads a single noisy step, the attack still works exactly as before. It reaches 96%,
  well above what ideal noise would allow.
- **Five steps:** when the sensor first adds up five noisy steps and uploads the sum (D2's FedAvg setting), the
  rounding fingerprints wash out. The best attack we could build then does exactly as well as an attacker facing
  perfect Gaussian noise, and no better.
- **Where N1 still applies:** the floating-point break holds only where a single step's noise leaves the device
  unsummed: FedSGD, or any protocol that releases every step's noisy gradient.
- **For D2 as designed:** the remaining N1 findings are hardening, not a break. They are the 5.77σ tail cap (modest),
  an instruction-path timing leak (phase-2 side channel) and the cost of a constant-time sampler.

## Setup

- **Code path:** the same M33 code as `experiments/n1-mcu-dp-sampler/attack.c` and D2's `mcu/dpstep.c`, using QEMU
  8.2.2 `mps2-an505` with bit-exact softfloat and newlib float32 libm. ChaCha20 supplies 24-bit uniforms for
  Box-Muller (MEASURED code path).
- **Adversary:** the worst-case DP adversary. It knows everything except the canary bit and the noise. σ = 0.451
  (ε = 8) and 0.798 (ε = 1), from D2's PRV accountant, with C = 1 (ASSUMPTION, as before).
- **Code:** `n1kill.c` (switches `SETTING`, `SIG_IDX`, `EVERY`), `n1kill.sh` and `n1kill_analyze.py`. Raw logs are in
  `experiments/n1-mcu-dp-sampler/results/2026-11-11/`.
- **Canary placement.** The old 86.6% / 73.4% bounds are *single-step* bounds. Once five steps are summed, the
  correct ideal bound depends on where the canary sits, so both placements were run:
  - **canary in step 1 only:** the usual case under DP-SGD subsampling. The noise grows √5 while the shift stays at C,
    so the bound *falls*.
  - **canary in all 5 steps:** D2's attack setup, with the same batch reused. The shift grows to 5C, so the bound
    *rises*.

## Is an exact search feasible? (settings 2 and 3)

**No.**
- **Setting 2:** one released pair now hides 5 Box-Muller pairs, each one of 2⁴⁸ possibilities. That is 2²⁴⁰
  preimages, against about 2⁶⁰ float32 output pairs. Meet-in-the-middle does not apply, because float addition with
  rounding is not a group operation.
- **More importantly, the search would be useless.** With about 2¹⁸⁰ preimages per output, *both* hypotheses have
  consistent noise for essentially every output. The "impossible under the wrong hypothesis" event that powered
  setting 1 disappears. This is arithmetic, and it is a CONJECTURE only in that it assumes the summed image is dense,
  which the bit tests below support.
- **Setting 3:** the same problem multiplied across 5 × 8,304 pairs, with the model changing between steps.

**The strongest practical attacks we ran:**
1. **LR test.** The Neyman–Pearson test for the Gaussian part: the nearest noiseless mean, using the full 16,608-dim
   update in setting 3. Any non-floating-point signal shows up here.
2. **BITS test.** A naive-Bayes classifier on low-order mantissa bits, trained on half the trials and tested on the
   other half. This is the only place float32 rounding structure could survive summation.
   - **Setting 2 features:** low 6 bits of y, of y − G₀, of y − G₁ and of the partner coordinate, plus an exponent
     comparison.
   - **Setting 3 features:** low 4 bits of the 32 most canary-sensitive coordinates.
3. **LR+BITS.** The two combined.

**Why these are the strongest we could justify in the time.**
- The LR test is optimal for the Gaussian component.
- A floating-point effect that survives five additions must leave a residue in the low-order bits or the rounding
  pattern, and the BITS test is a direct, learned search for exactly that.
- Anything subtler would need a model of the summed image, which is the infeasible part.

That feature encodes |y − G|, i.e. the same Gaussian magnitude information the LR test uses. Adding BITS to LR never
improves on LR alone, and with the canary in step 1 BITS is at chance (49.8–52.8%).

**How to read the setting-3 bounds.**
- My first bound used the attacker's *noiseless* trajectories to compute the separation (μ). The LR test beat it by
  3–6 points, which looked like leakage.
- A rerun exporting the LR margin settled it (`results/2026-11-11/s3_margin/`). The *empirical* separation of the LR
  statistic gives Gaussian-optimal accuracies of 59.0 / 88.0 / 55.4 / 73.9%, and the LR test sits on them (59.6 / 87.6 / 56.2 / 73.2%, all within about 1 SE of 1.1 points). The rerun reproduced the LR accuracies exactly (deterministic seeds).
- So the extra accuracy is ordinary Gaussian signal: noisy trajectories separate the hypotheses more than noiseless
  ones do. It is not floating-point leakage, and the floating-point-specific BITS test is at chance in all four
  configurations.

## What the attack still applies to (CONJECTURE unless marked)

- **FedSGD, or any protocol that uploads a single DP-SGD step's noisy gradient** (MEASURED: settings 1, 96%). This is
  the setting of Jin et al. and of TS-Inverse's threat model.
- **Any deployment where one Box-Muller pair lands unsummed in released values.** Examples are per-step release for
  auditing, local DP on sensor readings with float32 Box-Muller noise, and noisy telemetry. These are CONJECTURE: the
  same image-sparsity argument applies, but none was tested.
- **Not to D2's FedAvg with 5 local steps.** Settings 2 and 3 were MEASURED. They are also very likely not to apply
  after secure aggregation, which sums across clients (CONJECTURE).

## How strong the remaining N1 findings are

| Finding | Strength for D2 (FedAvg) | Label |
|---|---|---|
| 5.77σ tail cap (24-bit uniforms) | Exact accounting: δ 10⁻⁵ → 4.8×10⁻⁴ at ε = 8, and about +0.1 on ε at ε = 1, for *per-step* releases. With 5 steps summed, the cap moves to about 28.8σ per release and the effect is negligible. The concept is also already published (DP-Box, ISCA 2018). **Weak.** | MEASURED cap, computed accounting |
| Instruction-path leak in newlib float32 cosf/sinf | 1.22 of 2 bits of the pair's signs per pair; both signs guessed right 64.6% of the time (chance 25%). It is independent of summation, because it is observed on the device. It needs a physical (power/timing) adversary, so it is a phase-2 side-channel target. **Moderate, unproven on hardware.** | MEASURED (instruction counts, a timing proxy) |
| Cost of a constant-time integer sampler | 46–98 M instructions per step, 8–17× D2's DP step. Without the floating-point break in FedAvg, the motivation is defence in depth plus the timing leak. **Useful cost data, weaker motivation.** | ESTIMATE |

## Consequences

- **N1 card:**
  - Novelty for FedAvg goes from 3 to 2.
  - The headline is restricted to single-step / per-step releases.
  - Re-scored **24** (novelty 2, threat model 4, falsifiable 5, feasible 5, DRP 4, split 4).
- **D2 card:** N1 stays as a *hardening and side-channel* work package, not a "D2's noise is broken" claim. The
  phase-2 power analysis of the noise routine is unchanged.
- **Decision summary:** the recommendation to commit to D2 is unchanged. D2's score no longer counts an N1 security
  break in FedAvg.
